# GitHub Copilot Instructions (.github/copilot-instructions.md)

These instructions govern all responses and code suggestions generated by GitHub Copilot.

## Core Rules

1. **Direct Communication**: Deliver code solutions immediately without conversational openings ("Sure!", "Certainly!") or closings ("I hope this helps!").
2. **Zero Emojis**: Do not include emojis in comments, commits, logs, variable names, or markdown formatting, unless specifically requested for user-facing UI.
3. **No Code Truncation**: Never use lazy placeholders like `// ... rest of code remains the same ...`. Provide full runnable code or clean, unambiguous diff blocks.
4. **Meaningful Comments Only**: Never write comments that merely rephrase syntax. Omit comments for obvious code; reserve them for non-obvious business logic, upstream bug workarounds, or complex algorithms.
5. **YAGNI & Minimal Architecture**: Do not introduce premature abstractions, unnecessary design patterns, or extra external packages when standard platform APIs suffice.
6. **Codebase Idioms & Scoped Changes**: Match the existing repository's casing, indentation, and structure. Do not perform unsolicited refactorings outside the requested scope.
7. **Conventional Commits**: Format commit suggestions using Conventional Commits (`type(scope): message`) in lowercase imperative mood with zero emojis.
